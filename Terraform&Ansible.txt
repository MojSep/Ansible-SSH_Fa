۱️⃣ چرا هر دو؟ تفاوت بنیادین
تعریف کوتاه
ابزار	نقش	زبان	State
Terraform	ساختتغییرحذف زیرساخت	HCL	Stateful (.tfstate)
Ansible	پیکربندی سیستم‌های موجود	YAML	Stateless (idempotent)
تفاوت عمیق
ویژگی	Terraform	Ansible
فلسفه	Declarative infrastructure	ImperativeDeclarative config
State	فایل state (منبع حقیقت)	بدون state
Idempotency	State-based	Module-based
Drift detection	با terraform plan	با --check
Rollback	Manual (state surgery)	Manual (rerun playbook)
Lifecycle	CreateUpdateDestroy	فقط config
Scope	VPC, VM, DB, DNS, LB	OS, apps, services, config
زبان	HCL (declarative)	YAML (imperative)
Agent	ندارد (API)	ندارد (SSHAPI)
State management	Critical	Non-issue
Destroy	✅ بومی	❌ (فقط config)
چرا نمی‌توان یکی را جایگزین دیگری کرد؟

    ساخت VPC با subnetها

    مدیریت IAM roles با state

    ساخت RDS cluster

    مدیریت DNS records با state

۲️⃣ مدل ذهنی Provisioning vs Configuration
چرخه کامل یک سرویس
text

1. Terraform ساخت زیرساخت
   ├─ VPC
   ├─ Subnet
   ├─ Security Group
   ├─ EC2 instance
   └─ RDS

2. Ansible پیکربندی
   ├─ OS hardening
   ├─ nginx
   ├─ app code
   ├─ systemd service
   └─ monitoring agent

3. Ansible Deploy
   ├─ Pull code
   ├─ Migrate DB
   ├─ Restart service
   └─ Health check

4. Terraform destroy (اگر لازم)

۴.۶ الگوی حرفه‌ای null_resource + local-exec + triggers
hcl

resource null_resource configure_web {
  depends_on = [aws_instance.web, aws_security_group.web]

  triggers = {
    instance_ids = join(,, aws_instance.web[].id)
    playbook_hash = filemd5(${path.module}playbookssite.yml)
  }

  provisioner local-exec {
    command = -EOT
      set -e
      
      # 1. wait for SSH
      for ip in ${join( , aws_instance.web[].public_ip)}; do
        until nc -z -w 2 $ip 22; do
          echo Waiting for $ip...
          sleep 5
        done
      done
      
      # 2. generate inventory
      cat  tmpinventory-${self.id}.ini EOL
[webservers]
%{ for idx, ip in aws_instance.web[].public_ip ~}
web-${idx} ansible_host=${ip} ansible_user=ubuntu
%{ endfor ~}
EOL
      
      # 3. run playbook
      ansible-playbook 
        -i tmpinventory-${self.id}.ini 
        -e env=prod 
        --vault-password-file=etcansible.vault_pass 
        ${path.module}playbookssite.yml
    EOT
  }

  provisioner local-exec {
    when = destroy
    command = echo 'Cleanup instances going away'
  }
}

۵.۲ اجرای Terraform از Ansible
yaml

- name provision with terraform
  hosts localhost
  connection local

  tasks
    - name terraform init
      command terraform init
      args
        chdir {{ tf_dir }}
      register init
      changed_when 'Initializing' in init.stdout

    - name terraform plan
      command 
        terraform plan
        -var-file={{ env }}.tfvars
        -out=tfplan
      args
        chdir {{ tf_dir }}
      register plan
      changed_when 'No changes' not in plan.stdout

    - name terraform apply
      command terraform apply tfplan
      args
        chdir {{ tf_dir }}
      when plan.changed
      register apply

    - name get outputs
      command terraform output -json
      args
        chdir {{ tf_dir }}
      register outputs
      changed_when false

    - set_fact
        tf_out {{ outputs.stdout  from_json }}

    - name update inventory
      copy
        content 
          [webservers]
          {% for ip in tf_out.web_ips.value %}
          web-{{ loop.index0 }} ansible_host={{ ip }}
          {% endfor %}
        dest etcansibleinventoryprodhosts.ini

hcl

# null_resource با triggers دقیق
resource null_resource ansible_configure {
  depends_on = [
    aws_instance.web,
    aws_instance.db,
    aws_security_group.web,
  ]

  triggers = {
    web_instance_ids = join(,, aws_instance.web[].id)
    ansible_commit = var.ansible_commit_sha  # از CI
    config_hash = filemd5(${path.module}playbookssite.yml)
  }

  provisioner local-exec {
    command = ${path.module}scriptsrun-ansible.sh
    environment = {
      ANSIBLE_INVENTORY = aws_instance.web[0].public_ip
      ANSIBLE_CONFIG = etcansibleansible.cfg
      ENV = var.environment
      VAULT_PASS_FILE = etcansible.vault_pass
    }
  }

  provisioner local-exec {
    when = destroy
    command = ${path.module}scriptscleanup-ansible.sh
  }
}

bash

#!binbash
# scriptsrun-ansible.sh
set -euo pipefail

echo Waiting for SSH...
for i in {1..60}; do
  if nc -z -w 2 $ANSIBLE_INVENTORY 22; then
    echo SSH ready
    break
  fi
  sleep 5
done

echo Generating inventory...
cat  tmpinv-$$.ini EOF
[webservers]
${ANSIBLE_INVENTORY} ansible_user=ubuntu ansible_ssh_private_key_file=etcansiblekeysdeploy

[allvars]
ansible_python_interpreter=usrbinpython3
EOF

echo Running ansible-playbook...
ansible-playbook 
  -i tmpinv-$$.ini 
  -e env=${ENV} 
  --vault-password-file=${VAULT_PASS_FILE} 
  ${ANSIBLE_PLAYBOOK-playbookssite.yml}

echo Cleanup...
rm -f tmpinv-$$.ini

#!usrbinenv python3
# inventoryterraform_inventory.py

Reads Terraform state and builds Ansible inventory.
Usage .terraform_inventory.py --list

import json
import subprocess
import sys
import argparse
from pathlib import Path


def get_tf_state(tf_dir str) - dict
    زندگی‌تر از state
    result = subprocess.run(
        ['terraform', 'show', '-json'],
        cwd=tf_dir,
        capture_output=True,
        text=True,
        check=True,
    )
    return json.loads(result.stdout)


def build_inventory(state dict) - dict
    inventory = {
        '_meta' {'hostvars' {}},
        'all' {'children' []},
    }
    
    resources = state.get('values', {}).get('root_module', {}).get('resources', [])
    
    for r in resources
        r_type = r.get('type')
        r_name = r.get('name')
        values = r.get('values', {})
        
        # EC2 instances
        if r_type == 'aws_instance'
            instance_id = values.get('id', '')
            ip = values.get('public_ip') or values.get('private_ip')
            name = values.get('tags', {}).get('Name', f'instance-{instance_id[8]}')
            
            # groups based on tags
            tags = values.get('tags', {})
            role = tags.get('Role', 'ungrouped')
            env = tags.get('Environment', 'unknown')
            
            groups = [role, env, f'{role}_{env}']
            
            for g in groups
                if g not in inventory
                    inventory[g] = {'hosts' []}
                inventory[g]['hosts'].append(name)
            
            inventory['_meta']['hostvars'][name] = {
                'ansible_host' ip,
                'ansible_user' 'ubuntu',
                'ansible_ssh_private_key_file' 'etcansiblekeysdeploy',
                'instance_id' instance_id,
                'instance_type' values.get('instance_type'),
                'environment' env,
                'role' role,
            }
    
    inventory['all']['children'] = [k for k in inventory if k not in ('_meta', 'all')]
    return inventory


def main()
    parser = argparse.ArgumentParser()
    parser.add_argument('--list', action='store_true')
    parser.add_argument('--host')
    parser.add_argument('--tf-dir', default='.')
    args = parser.parse_args()
    
    state = get_tf_state(args.tf_dir)
    
    if args.list
        print(json.dumps(build_inventory(state), indent=2))
    elif args.host
        inv = build_inventory(state)
        print(json.dumps(inv['_meta']['hostvars'].get(args.host, {})))


if __name__ == '__main__'
    main()

# inventory_pluginstfstate.py
from ansible.plugins.inventory import BaseInventoryPlugin
import json
import subprocess

DOCUMENTATION = '''
name tfstate
plugin_type inventory
options
  plugin
    required true
    choices ['tfstate']
  project_dir
    required true
  binary
    default terraform
'''

class InventoryModule(BaseInventoryPlugin)
    NAME = 'tfstate'

    def verify_file(self, path)
        return path.endswith(('.tfstate.yml', '.tfstate.yaml'))

    def parse(self, inventory, loader, path, cache=True)
        super().parse(inventory, loader, path)
        self._read_config_data(path)
        
        project_dir = self.get_option('project_dir')
        binary = self.get_option('binary')
        
        result = subprocess.run(
            [binary, 'show', '-json'],
            cwd=project_dir,
            capture_output=True,
            text=True,
            check=True,
        )
        state = json.loads(result.stdout)
        
        for r in state['values']['root_module'].get('resources', [])
            if r['type'] != 'aws_instance'
                continue
            
            values = r['values']
            host = values.get('tags', {}).get('Name', values['id'][12])
            ip = values.get('public_ip') or values.get('private_ip')
            
            self.inventory.add_host(host)
            self.inventory.set_variable(host, 'ansible_host', ip)
            self.inventory.set_variable(host, 'ansible_user', 'ubuntu')
            
            for group in [values.get('tags', {}).get('Role', 'web'),
                          values.get('tags', {}).get('Environment', 'prod')]
                self.inventory.add_group(group)
                self.inventory.add_child(group, host)

Ansible rollback
bash

ansible-playbook rollback.yml --limit=affected

Combined rollback
yaml

- hosts localhost
  tasks
    - name terraform rollback
      git
        repo httpsgithub.comorgtf-infra.git
        dest optterraform
        version {{ rollback_sha }}
        force yes

    - name apply old
      community.general.terraform
        project_path optterraform
        state present

- hosts affected
  tasks
    - name ansible rollback
      include_role
        name rollback

۲۴️⃣ Anti-Patterns
❌ ۱. local-exec بدون depends_on
hcl

# ❌ race condition
resource aws_instance web {
  provisioner local-exec {
    command = ansible-playbook site.yml
  }
}

hcl

# ✅
resource null_resource config {
  depends_on = [aws_instance.web]
  provisioner local-exec {
    command = ansible-playbook site.yml
  }
}

❌ ۲. Config در Terraform
hcl

# ❌ nginx config با Terraform
resource null_resource nginx {
  provisioner remote-exec {
    inline = [echo 'server {}'  etcnginxnginx.conf]
  }
}

yaml

# ✅
- name nginx config
  template
    src nginx.conf.j2
    dest etcnginxnginx.conf
  notify reload nginx

❌ ۳. Provision در Ansible
yaml

# ❌ ساخت VPC با Ansible
- amazon.aws.ec2_vpc_net
    name my-vpc
    cidr_block 10.0.0.016

hcl

# ✅
resource aws_vpc main {
  cidr_block = 10.0.0.016
}

❌ ۵. Secret در user_data
hcl

# ❌ لاگ می‌شود

❌ ۶. بدون lock
hcl

# ❌ بدون DynamoDB

hcl

# ✅

  backend s3 {
    bucket         = ...
    dynamodb_table = tf-lock
  }
}

hcl

  source = terraform-aws-modulesvpcaws

# ✅

  source  = terraform-aws-modulesvpcaws

}

۲۵️⃣ Best Practices
معماری

    Terraform = infrastructure, Ansible = config

    State جدا per environment (prod  staging  dev)

    Backend remote با lock (S3 + DynamoDB یا TFC)

    Pipeline یکپارچه (validate → plan → apply → configure → verify)

    Inventory تولیدشده از Terraform state (نه hardcode)

Terraform

    Module pin شده (version = x.y.z)

    terraform fmt + terraform validate در CI

    terraform plan -out + review

    tflint + checkov برای security scan

    sensitive = true برای outputs حساس

    prevent_destroy برای resourceهای حیاتی

    Workspaces یا دایرکتوری جدا برای هر env

Ansible

    --check --diff در staging

    serial برای rolling

    no_log true روی secrets

    validate در config

    Idempotency test (دو بار → changed=0)

    ansible-lint --profile production

Integration

    Inventory از Terraform (dynamic یا generated)

    Secret manager مشترک (Vault  AWS SM)

    null_resource + triggers نه local-exec خالی

    Bash script جدا برای complex logic

    Drift detection (هر ۶ ساعت)

Security

    State encrypt (S3 SSE-KMS)

    State lock (DynamoDB)

    Access control (IAM role  OIDC)

    No secrets in user_data (استفاده از SSMSecrets Manager)

    Vault برای هر دو (Ansible + Terraform)

    Audit log روی applyconfigure

    RBAC روی state bucket و ansible control node

Operations

    Tag همه چیز (Environment, ManagedBy=Terraform, Role)

    Monitoring (CloudWatch + Prometheus)

    Runbook برای هر pipeline

    Rollback plan در هر PR

    Cost tagging (FinOps)

🎓 ۱۰ قانون طلایی برای Ansible + Terraform

    Terraform بساز، Ansible پیکربندی کن — تفکیک مسئولیت

    State جدا per env — prod هرگز با staging قاطی نشود

    Inventory از Terraform state — نه hardcode

    null_resource + triggers — نه local-exec بدون context

    Secret manager مشترک (Vault) — نه plaintext

    terraform plan در PR — قبل از apply

    --check --diff در staging — قبل از prod

    Idempotency در هر دو — test شده

    Drift detection — هر ۶ ساعت

    Rollback plan — در هر PR
