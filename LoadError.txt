🚨 راهنمای جامع خطاهای Ansible: از لود اولیه تا اجرای Playbook + دلایل و راه‌حل‌ها

    ساختار هر خطا: پیام خطا → علت فنی → تشخیص → راه‌حل → پیشگیری

📦 بخش ۱: خطاهای نصب و لود اولیه (Ansible اصلاً اجرا نمی‌شود)
1.1 ansible: command not found

علت: Ansible نصب نیست یا در $PATH نیست.
تشخیص:
bash

which ansible
python3 -c "import ansible; print(ansible.__version__)"
pip3 show ansible ansible-core
echo $PATH

راه‌حل:
bash

# روش پیشنهادی: virtualenv
python3 -m venv /opt/ansible-venv
/opt/ansible-venv/bin/pip install ansible-core
export PATH=/opt/ansible-venv/bin:$PATH

# یا apt/dnf
sudo apt install ansible-core       # Debian/Ubuntu
sudo dnf install ansible-core       # RHEL/Rocky

پیشگیری: نصب در venv، ثبت در ~/.bashrc، یا استفاده از pipx install ansible-core.
1.2 ImportError: No module named ansible

علت: پایتون اشتباه (system python vs venv)، نصب ناقص، یا PYTHONPATH مخدوش.
تشخیص:
bash

head -1 $(which ansible)     # shebang → کدام python؟
pip3 list | grep ansible
python3 -c "import sys; print(sys.path)"

راه‌حل:
bash

pip3 install --upgrade ansible-core
# یا نصب مجدد در venv
unset PYTHONPATH

پیشگیری: venv جدا، پرهیز از pip install --user روی سیستم‌های shared.
1.3 ModuleNotFoundError: No module named 'jinja2'

علت: وابستگی ناقص یا نصب نیمه‌کاره.
راه‌حل:
bash

pip3 install -r $(python3 -c "import ansible, os; print(os.path.dirname(ansible.__file__))")/../ansible_core*/requirements.txt
# یا ساده‌تر:
pip3 install --upgrade --force-reinstall ansible-core

پیشگیری: استفاده از pip check برای بررسی سازگاری.
1.4 ansible: error while loading shared libraries: libpython3.X.so.1.0: cannot open shared object file

علت: کتابخانه Python حذف/جابجا شده یا نسخه اشتباه python.
تشخیص:
bash

ldd $(which ansible)
ls /usr/lib/x86_64-linux-gnu/libpython3*

راه‌حل:
bash

sudo apt install --reinstall libpython3.10 python3.10
sudo ldconfig

1.5 ERROR! Unexpected Exception, this is probably a bug: (your error)

علت: استثنای غیرمنتظره در core.
تشخیص:
bash

ansible --version
ansible-playbook -vvv playbook.yml
ANSIBLE_DEBUG=1 ansible-playbook playbook.yml

راه‌حل: گزارش به issues با ansible-playbook -vvvv؛ در موقت:
bash

pip3 install --upgrade ansible-core

1.6 command not found: ansible-playbook (ولی ansible هست)

علت: نصب ansible-core بدون ansible bundle، یا PATH ناقص.
راه‌حل:
bash

ls /usr/bin/ansible*
pip3 install ansible  # meta-package

1.7 ERROR! 'ansible' is not a valid attribute for a Play

علت: YAML playbook فاقد ساختار list of dicts است یا کلید اشتباه.
تشخیص:
yaml

# ❌ اشتباه
ansible: ...
# ✅ درست
- hosts: all
  tasks: [...]

راه‌حل: ansible-lint بزن؛ yamllint playbook.yml.
⚙️ بخش ۲: خطاهای ansible.cfg
2.1 [WARNING]: Config file (...) could not be found

علت: $ANSIBLE_CONFIG به مسیر ناموجود اشاره می‌کند.
تشخیص: echo $ANSIBLE_CONFIG ، ansible-config view
راه‌حل: unset ANSIBLE_CONFIG یا مسیر صحیح.
2.2 [WARNING]: Ansible is being run in a world writable directory

علت: اجرا از دایرکتوری که world-writable است (مثلاً /tmp)، Ansible فایل ansible.cfg محلی را نادیده می‌گیرد.
راه‌حل:
bash

chmod o-w /path/to/project
# یا انتقال به مسیر امن

امنیتی: این هشدار جدی است — مهاجم می‌تواند ansible.cfg مخرب قرار دهد.
2.3 [WARNING]: provided hosts list is empty, only localhost is available

علت: inventory خالی، مسیر اشتباه، یا فایل parse نشده.
تشخیص:
bash

ansible-inventory --list
ansible-inventory --graph
ansible all --list-hosts

راه‌حل:

    بررسی inventory = در ansible.cfg

    ansible -i /path/to/inventory all --list-hosts

    اگر inventory دایرکتوری است: ls -la و بررسی پسوندها

2.4 ERROR! Invalid settings supplied for ...

علت: کلید ناشناخته یا مقدار نامعتبر در ansible.cfg.
تشخیص:
bash

ansible-config dump --only-changed
ansible-config dump 2>&1 | grep -i invalid

راه‌حل: مراجعه به ansible-config list برای دیدن نام دقیق کلیدها و بخش ([defaults], [ssh_connection], …).
2.5 [WARNING]: * Failed to parse ... with ini plugin: ...

علت: inventory INI با ساختار اشتباه (مثلاً [group:vars] بدون =).
تشخیص: ansible-inventory -i file.ini --list
راه‌حل: اصلاح INI؛ یا inventory_unparsed_failed = True برای fail سریع.
2.6 [WARNING]: Invalid characters in ...

علت: کاراکتر غیرمجاز در نام گروه/میزبان یا مسیر.
راه‌حل: فقط [a-zA-Z0-9_-.] (بدون فاصله، :, /).
2.7 Deprecation warnings ... ansible.cfg ...

علت: کلید در نسخه جدید منسوخ شده (use_ssh_args, accelerate, …).
راه‌حل: ansible-config list | grep -B1 deprecated → انتقال به کلید جدید.
2.8 [WARNING]: log file at ... is not writeable and we cannot create it, aborting

علت: log_path با مجوز نادرست.
راه‌حل:
bash

sudo touch /var/log/ansible.log
sudo chown ansible:adm /var/log/ansible.log
sudo chmod 640 /var/log/ansible.log

🌐 بخش ۳: خطاهای Inventory
3.1 Unable to parse /etc/ansible/hosts as an inventory source

علت: فایل خالی، YAML نامعتبر، پسوند ناشناخته، یا permission.
تشخیص:
bash

file /etc/ansible/hosts
python3 -c "import yaml; print(yaml.safe_load(open('/etc/ansible/hosts')))"
ansible-inventory -i /etc/ansible/hosts --list -vvv

راه‌حل: اصلاح ساختار؛ افزودن پسوند صحیح؛ chmod 644.
3.2 Attempted to read ... as JSON

علت: inventory با پسوند .json ولی محتوای YAML/INI.
راه‌حل: نام‌گذاری درست یا enable_plugins صریح.
3.3 [WARNING]: Could not match supplied host pattern, ignoring: <pattern>

علت: پترن در hosts: وجود ندارد.
تشخیص:
bash

ansible-inventory --graph
ansible-inventory --host <name>

راه‌حل: اصلاح نام؛ all، الگو web*، یا ansible-inventory --graph برای دیباگ.
3.4 [WARNING]: Unable to parse ... as an inventory source + Ignoring ...

علت: پلاگین script یا auto روی فایل اجرایی نامعتبر.
راه‌حل: enable_plugins = yaml, ini یا افزودن shebang صحیح به اسکریپت.
3.5 Invalid data from file, expected dictionary and got ...

علت: ساختار YAML inventory با تودرتویی اشتباه.
راه‌حل: نمونه صحیح YAML:
yaml

all:
  children:
    web:
      hosts:
        web01: {}

3.6 Could not find the requested inventory source ...

علت: مسیر در -i وجود ندارد.
راه‌حل: ls -la روی مسیر؛ مسیر مطلق ده.
3.7 Cannot parse ... unhashable type 'dict'

علت: دیکشنری داخل hosts: یا children: در محل غیرمجاز.
راه‌حل: بررسی نمونه YAML و ساختار children/hosts.
3.8 [WARNING]: * Failed to parse ... with yaml plugin: YAML inventory has invalid structure, it should be a dictionary

علت: YAML inventory با root لیست.
راه‌حل: root باید dict باشد با all یا نام گروه.
3.9 Inventory hostname ... has invalid characters

علت: کاراکتر غیرمجاز در نام.
راه‌حل: [a-zA-Z0-9_.-] فقط.
3.10 hosts variable has no 'hosts' key (برای پلاگین داینامیک)

علت: پلاگین inventory داینامیک (aws_ec2, azure_rm, ...) تنظیمات ناقص/plugin نصب نیست.
راه‌حل:
bash

ansible-galaxy collection install amazon.aws
ansible-inventory -i inventory_aws_ec2.yml --graph -vvv

بررسی plugin: و credentialها.
🔌 بخش ۴: خطاهای اتصال SSH
4.1 UNREACHABLE! => {"msg": "Failed to connect to the host via ssh: ssh: connect to host ... port 22: Connection refused"}

علت: سرویس SSH خاموش، فایروال، پورت اشتباه.
تشخیص:
bash

nc -zv host 22
ssh -vvv user@host
ansible host -m ping -vvv

راه‌حل: روشن کردن sshd؛ remote_port صحیح؛ فایروال.
4.2 Permission denied (publickey,password)

علت: کلید اشتباه، کاربر اشتباه، authorized_keys.
تشخیص:
bash

ssh -i ~/.ssh/key -o IdentitiesOnly=yes user@host
ssh-add -l

راه‌حل:
yaml

# در inventory
ansible_host=...
ansible_user=...
ansible_ssh_private_key_file=~/.ssh/id_rsa

یا ssh-agent + ssh-add.
4.3 Host key verification failed

علت: fingerprint تغییر کرده / نبود در known_hosts (با host_key_checking=True).
تشخیص:
bash

ssh-keygen -F hostname
ssh-keyscan -t ed25519 host

راه‌حل:
bash

ssh-keygen -R host
ssh-keyscan -H host >> ~/.ssh/known_hosts

امنیتی: هرگز host_key_checking=False در prod — از CA امضاکننده استفاده کن.
4.4 SSH Error: data could not be sent to remote host

علت: timeout، قطعی شبکه، pipelining با requiretty، ControlPersist سوکت خراب.
تشخیص:
bash

ls -la ~/.ansible/cp/
ssh -o ControlPath=... user@host

راه‌حل:
bash

rm -rf ~/.ansible/cp/*
ansible-playbook --ssh-extra-args="-o ConnectTimeout=30"

یا pipelining=False موقتاً.
4.5 Missing sudo password

علت: become: true ولی become_ask_pass یا NOPASSWD تنظیم نشده.
راه‌حل:

    ansible-playbook -K (پرسیدن رمز)

    یا در sudoers:

text

ansible ALL=(ALL) NOPASSWD: ALL
Defaults:ansible !requiretty

    یا become_ask_pass = True در ansible.cfg.

4.6 sudo: sorry, you must have a tty to run sudo

علت: requiretty فعال + pipelining.
راه‌حل:
text

# /etc/sudoers
Defaults !requiretty
Defaults:ansible !requiretty

یا pipelining = False (کاهش سرعت).
4.7 Authentication or permission failure. In some cases, you may have been able to authenticate and did not have permissions on the target directory

علت: کاربر SSH به ~/.ansible/tmp دسترسی ندارد.
راه‌حل:
yaml

# inventory
ansible_remote_tmp=/tmp/.ansible-${USER}/tmp

یا در ansible.cfg: remote_tmp = /tmp/.ansible-${USER}/tmp.
4.8 to use the 'ssh' connection type with passwords or pkcs11-provider, you must install the sshpass program

علت: اتصال با رمز SSH بدون sshpass.
راه‌حل: sudo apt install sshpass (توصیه نمی‌شود) — بهتر: از کلید استفاده کن.
4.9 Timeout (12s) waiting for privilege escalation prompt

علت: sudo منتظر رمز است ولی become_ask_pass تنظیم نشده، یا sudoers کند است (LDAP).
راه‌حل:

    -K یا become_ask_pass=True

    افزایش timeout = 30

    sudo بدون NOPASSWD/pam ساده

4.10 Control socket ... already exists, disabling multiplexing

علت: سوکت قدیمی در ~/.ansible/cp/.
راه‌حل:
bash

rm -rf ~/.ansible/cp/*

4.11 Cannot use pipelining with sudo / pipelining errors

علت: requiretty یا sudo در حالت -S بدون TTY.
راه‌حل: Defaults !requiretty + pipelining=True یا pipelining=False.
4.12 ssh: Could not resolve hostname <host>

علت: DNS//etc/hosts روی control node.
راه‌حل:
bash

getent hosts <host>
ping -c1 <host>

یا ansible_host= با IP در inventory.
4.13 Connection reset by peer

علت: فایروال، IDS/IPS، sshd حداکثر اتصال، MaxStartups.
راه‌حل: افزایش MaxStartups در sshd_config؛ کاهش forks؛ بررسی fail2ban.
🐍 بخش ۵: خطاهای Python Interpreter
5.1 The module failed to execute correctly, you probably need to set the interpreter

پیام کامل: /usr/bin/python: not found
علت: هاست هدف python ندارد یا مسیرش /usr/bin/python3 است.
راه‌حل:
ini

# ansible.cfg
interpreter_python = /usr/bin/python3

# یا در inventory
ansible_python_interpreter=/usr/bin/python3

یا ansible_python_interpreter=auto_silent.
5.2 MODULE FAILURE + SyntaxError

علت: نسخه Python روی هدف قدیمی (2.7) و ماژول نیاز به 3.x دارد.
راه‌حل: ارتقاء Python؛ یا ماژول سازگار؛ ansible_python_interpreter=/usr/bin/python3.10.
5.3 Could not find a suitable Python interpreter

علت: هیچ‌کدام از مفسرهای fallback موجود نیست.
راه‌حل:
yaml

# در inventory vars
ansible_python_interpreter: /usr/local/bin/python3.11

برای Alpine: apk add python3.
برای RHEL: dnf install python3.
5.4 python3: not found روی Alpine

علت: Alpine به‌طور پیش‌فرض پایتون ندارد.
راه‌حل:
yaml

- raw: apk add --no-cache python3
  when: ansible_os_family == "Alpine"

در playbook اولیه (gather_facts: false).
5.5 ImportError: No module named 'selinux'

علت: روی هدف libselinux-python نصب نیست.
راه‌حل:
bash

sudo dnf install python3-libselinux   # RHEL
sudo apt install python3-selinux      # Debian

5.6 ImportError: No module named 'apt' / 'yum' / 'dnf'

علت: وابستگی ماژول (pycurl, libvirt-python, …) روی هدف نیست.
راه‌حل:
bash

sudo apt install python3-apt
sudo dnf install python3-dnf

📦 بخش ۶: خطاهای ماژول و Plugin
6.1 The module <name> was not found in configured module paths

علت: ماژول core نیست، collection نصب نیست.
تشخیص:
bash

ansible-doc -l | grep <module>
ansible-galaxy collection list

راه‌حل:
bash

ansible-galaxy collection install community.general
# در playbook:
collections:
  - community.general

یا FQCN: community.general.<module>.
6.2 ERROR! couldn't resolve module/action 'xxx'

علت: FQCN اشتباه یا collection نیست.
راه‌حل: ansible-doc -l | grep <name>؛ نصب collection.
6.3 Could not find or access '/path/to/file'

علت: src در copy/template/script وجود ندارد یا نسبی اشتباه.
تشخیص:
bash

ls roles/<role>/files/
ls roles/<role>/templates/

راه‌حل: مسیر نسبی از playbook_dir/role/files؛ -vvv برای دیدن مسیر resolve.
6.4 MODULE FAILURE\nSee stdout/stderr for the exact error

علت: خطای اجرای ماژول (permission, syntax, dependency).
تشخیص:
bash

ansible host -m <module> -a '...' -vvv

یا با -e ansible_keep_remote_files=true فایل temp روی هدف نگه داشته می‌شود.
6.5 Traceback ... No module named 'requests'

علت: ماژول (uri, get_url, ...) نیاز به requests روی هدف دارد.
راه‌حل:
bash

sudo apt install python3-requests

یا pip3 install requests روی هدف.
6.6 TypeError: ... unexpected keyword argument

علت: نسخه module قدیمی با playbook جدید.
راه‌حل: ansible-galaxy collection install --upgrade <collection>؛ ansible-doc <module>.
6.7 Failed to find required executable ...

علت: باینری موردنیاز روی هدف نیست (git, rsync, systemctl, ...).
راه‌حل: نصب باینری؛ یا state skip.
6.8 The task includes an option with an undefined variable

علت: متغیر تعریف‌نشده.
تشخیص:
bash

ansible-playbook --syntax-check
ansible-playbook -vvv --start-at-task="..."

راه‌حل: default() در Jinja؛ vars_prompt؛ set_fact.
6.9 'dict object' has no attribute '...'

علت: کلید در dict نیست (typo یا fact نبود).
راه‌حل:
yaml

"{{ my_dict.get('key', 'default') }}"

و -vvv برای دیدن مقدار.
6.10 Recursive loop detected in template string

علت: self-reference در Jinja.
راه‌حل: تغییر نام متغیر یا استفاده از set_fact.
