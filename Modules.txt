🧰 ماژول‌های پرکاربرد و حرفه‌ای Ansible در محیط‌های عملیاتی

    این مرجع بر اساس استفاده واقعی در تیم‌های DevOps/SRE/Infrastructure است. هر ماژول با کاربرد → پارامترهای کلیدی → return values مهم → مثال production → نکات فنی و gotchaها → ملاحظات امنیتی توضیح داده می‌شود.

📦 دسته ۱: مدیریت پکیج‌ها (Package Management)
۱.۱ ansible.builtin.apt / ansible.builtin.dnf / ansible.builtin.yum

کاربرد: نصب/حذف/ارتقاء پکیج روی Debian/Ubuntu (apt) و RHEL/Rocky/Alma (dnf/yum).

پارامترهای کلیدی production:
yaml

apt:
  name:                    # لیست یا string
  state:                   # present | absent | latest | build-dep | fixed
  update_cache:            # yes|no → اجرای apt update
  cache_valid_time:        # ثانیه → اگر cache تازه‌تر، update نکن
  autoremove:              # yes → پاک کردن وابستگی‌های بدون استفاده
  purge:                   # yes → حذف فایل‌های config
  deb:                     # مسیر فایل .deb محلی یا URL
  install_recommends:      # no → نصب نکردن recommends
  allow_unauthenticated:   # no (پیش‌فرض) → فقط بسته‌های امضا‌شده
  dpkg_options:            # "force-confdef,force-confold"
  force_apt_get:           # yes → استفاده از apt-get به‌جای apt

yaml

dnf:
  name:
  state:                   # present | absent | latest
  enablerepo:              # فعال‌سازی repo خاص
  disablerepo:
  update_cache:            # yes
  autoremove:
  security:                # yes → فقط security updates (با state=latest)
  bugfix:                  # yes → فقط bugfix
  exclude:                 # پکیج‌های استثنا
  disable_gpg_check:       # ⚠️ never in production
  skip_broken:             # no (پیش‌فرض)

Return values مهم:

    changed, failed

    results[] برای هر پکیج: name, version, state

    cache_updated

مثال production (multi-distro):
yaml

- name: install security packages
  package:
    name: "{{ pkg_list }}"
    state: present
  vars:
    pkg_list:
      - curl
      - vim
      - htop
      - python3-apt
      - ca-certificates

- name: install from local .deb
  apt:
    deb: /tmp/myapp_1.2.3_amd64.deb
    state: present

- name: hold critical package
  dpkg_selections:
    name: openssh-server
    selection: hold

- name: security updates only (RHEL)
  dnf:
    name: "*"
    state: latest
    security: yes
    update_cache: yes
  when: ansible_os_family == "RedHat"

نکات فنی و gotchaها:

    state: latest = non-idempotent در ظاهر (always reports changed اگر update موجود باشد)

    cache_valid_time: 3600 روی apt → سرعت بالا در اجراهای مکرر

    update_cache: yes روی هر task = کند؛ فقط یک بار اجرا کن

    برای apt با unattended-upgrades: APT::Periodic → apt lock

    force_apt_get: yes برای محیط‌های غیرتعاملی (CI)

    روی RHEL 8+: همیشه dnf نه yum (yum لایه سازگاری است)

ملاحظات امنیتی:

    هرگز disable_gpg_check: yes

    allow_unauthenticated: no (پیش‌فرض)

    برای apt: apt_repository با signed-by keyring

    pin کردن نسخه در محیط حساس

۱.۲ ansible.builtin.package (Generic)

کاربرد: ماژول abstraction که خودش تشخیص می‌دهد apt یا dnf یا zypper.

پارامترها:
yaml

package:
  name:                    # فقط نام و state پشتیبانی می‌شوند
  state:                   # present | absent | latest
  use:                     # apt|dnf|yum|zypper|pacman → override auto-detection

مثال:
yaml

- package:
    name: [nginx, curl]
    state: present
  when: ansible_pkg_mgr in ['apt', 'dnf', 'yum']

نکته: برای پارامترهای اختصاصی OS (مثلاً cache_valid_time)، از ماژول صریح استفاده کن.
۱.۳ ansible.builtin.pip

کاربرد: نصب پکیج پایتون روی هاست هدف یا در venv.
yaml

pip:
  name:                    # string یا list
  version:                 # ==1.2.3 | >=1.0 | latest
  state:                   # present | absent | latest | forcereinstall
  virtualenv:              # مسیر venv
  virtualenv_command:      # python3 -m venv
  virtualenv_python:       # /usr/bin/python3.11
  requirements:            # مسیر requirements.txt
  extra_args:              # "--index-url https://..."
  umask:
  executable:              # /usr/local/bin/pip3
  chdir:                   # دایرکتوری اجرا

مثال production (multi-venv):
yaml

- name: ensure venv
  command: python3 -m venv /opt/app/venv
  args: { creates: /opt/app/venv/bin/activate }

- name: install requirements
  pip:
    requirements: /opt/app/requirements.txt
    virtualenv: /opt/app/venv
    virtualenv_python: /usr/bin/python3.11
    extra_args: "--no-cache-dir --require-hashes"
  register: pip_result

نکات:

    --require-hashes برای production (تأیید checksum)

    virtualenv_command باید صریح باشد (بعضی سیستم‌ها default ندارند)

    state: latest در pip = non-idempotent

۱.۴ ansible.builtin.apt_repository / ansible.builtin.yum_repository

کاربرد production: افزودن mirror داخلی، repo اختصاصی، repo با GPG key.
yaml

- name: add internal mirror
  apt_repository:
    repo: "deb [signed-by=/etc/apt/keyrings/internal.gpg] https://mirror.internal/ubuntu jammy main"
    state: present
    filename: internal
    update_cache: yes

- name: add GPG key
  apt_key:
    url: https://mirror.internal/key.gpg
    keyring: /etc/apt/keyrings/internal.gpg
    state: present

yaml

- name: add repo (RHEL)
  yum_repository:
    name: epel
    description: EPEL
    baseurl: https://mirror.internal/epel/$releasever/$basearch/
    gpgcheck: yes
    gpgkey: https://mirror.internal/RPM-GPG-KEY-EPEL-9
    enabled: yes

ملاحظات امنیتی:

    signed-by در apt keyring اجباری

    gpgcheck: yes هرگز تغییر نده

    keyring path: /etc/apt/keyrings/ (نه /etc/apt/trusted.gpg.d/ که deprecated است)

⚙️ دسته ۲: مدیریت سرویس‌ها
۲.۱ ansible.builtin.systemd / ansible.builtin.service

کاربرد: کنترل چرخه حیات سرویس.
yaml

systemd:
  name:
  state:                   # started | stopped | restarted | reloaded
  enabled:                 # yes|no
  masked:                  # yes|no
  daemon_reload:           # yes → بعد از تغییر unit
  daemon_reexec:           # yes → systemctl daemon-reexec
  no_block:                # yes → non-blocking (برای reboot)
  scope:                   # system | user
  force:                   # yes → override

Return values: status.{ActiveState, SubState, LoadState}, changed

مثال production:
yaml

- name: change systemd unit
  template:
    src: myapp.service.j2
    dest: /etc/systemd/system/myapp.service
  notify:
    - reload systemd
    - restart myapp

- name: start app
  systemd:
    name: myapp
    state: started
    enabled: yes
    daemon_reload: yes

- name: reload only if config changed
  systemd:
    name: nginx
    state: reloaded
  when: nginx_config.changed

Handlers استاندارد:
yaml

handlers:
  - name: reload systemd
    systemd: { daemon_reload: yes }
  - name: restart myapp
    systemd: { name: myapp, state: restarted, daemon_reload: yes }

نکات فنی:

    daemon_reload: yes اجباری بعد از تغییر unit

    برای state: reloaded → فقط اگر سرویس ExecReload داشته باشد

    masked: yes = جلوگیری کامل از start (حتی دستی)

    اگر container است: service_mgr را چک کن (when: ansible_service_mgr == 'systemd')

📁 دسته ۳: فایل و تمپلیت
۳.۱ ansible.builtin.copy

کاربرد production: توزیع فایل کانفیگ، backup، استقرار artifact.
yaml

copy:
  src:                    # مسیر محلی یا remote (با remote_src=yes)
  dest:                   # مسیر هدف
  content:                # به‌جای src → string
  owner/group/mode:       # '0644' → همیشه به‌صورت string
  backup:                 # yes → timestamped backup
  force:                  # yes|no
  remote_src:             # yes → از هدف به هدف
  validate:               # "nginx -t -c %s"
  directory_mode:         # برای directory
  follow:                 # yes → symlink target
  checksum:               # sha1:... → idempotency

Return values: changed, checksum, dest, backup_file

مثال production:
yaml

- name: deploy config with validation
  copy:
    src: nginx.conf
    dest: /etc/nginx/nginx.conf
    owner: root
    group: root
    mode: '0644'
    backup: yes
    validate: 'nginx -t -c %s'
  notify: restart nginx

- name: deploy binary
  copy:
    src: "dist/app-{{ version }}"
    dest: /opt/app/app
    mode: '0755'
    checksum: "sha256:{{ app_sha256 }}"

نکات:

    mode: '0644' (با کوتیشن) → اجتناب از interpret به octal

    validate قبل از جایگزینی → فایل ناسالم مستقر نمی‌شود

    checksum برای idempotency قوی

    برای فایل‌های بزرگ: synchronize یا unarchive سریع‌تر

۳.۲ ansible.builtin.template (Jinja2)

کاربرد production: تولید configهای پویا (بر اساس fact، env، version).
yaml

template:
  src:                    # *.j2
  dest:
  owner/group/mode:
  backup:
  validate:               # ← حیاتی
  trim_blocks:            # yes → حذف newline بعد از block
  lstrip_blocks:          # yes → trim leading whitespace
  newline_sequence:       # '\n' | '\r\n'
  block_start_string:     # '{%' | ...
  variable_start_string:  # '{{' | ...
  variable_end_string:    # '}}' | ...

مثال production (multi-env):
yaml

# templates/nginx.conf.j2
user {{ nginx_user | default('www-data') }};
worker_processes {{ ansible_processor_vcpus }};
{% if env == 'production' %}
worker_rlimit_nofile 65535;
{% endif %}
events {
    worker_connections {{ nginx_worker_connections | default(1024) }};
}
http {
    sendfile on;
    keepalive_timeout {{ nginx_keepalive | default(65) }};
    {% for upstream in nginx_upstreams %}
    upstream {{ upstream.name }} {
        {% for server in upstream.servers %}
        server {{ server }};
        {% endfor %}
    }
    {% endfor %}
}

yaml

- template:
    src: nginx.conf.j2
    dest: /etc/nginx/nginx.conf
    mode: '0644'
    validate: 'nginx -t -c %s'
    trim_blocks: yes
    lstrip_blocks: yes
  notify: reload nginx

نکات:

    validate اجباری برای configهای حساس

    trim_blocks + lstrip_blocks = خروجی تمیز

    برای % (nginx): {% raw %}...{% endraw %}

    ansible_managed در header برای هشدار "do not edit"

۳.۳ ansible.builtin.lineinfile / blockinfile / replace

کاربرد production: تغییر فایل سیستمی موجود (نه جایگزینی کامل).
yaml

- name: disable root login
  lineinfile:
    path: /etc/ssh/sshd_config
    regexp: '^#?\s*PermitRootLogin'
    line: 'PermitRootLogin no'
    state: present
    backup: yes
    validate: 'sshd -t -f %s'

- name: append if not exists
  lineinfile:
    path: /etc/environment
    line: 'JAVA_HOME=/usr/lib/jvm/default-java'
    state: present

- name: remove line
  lineinfile:
    path: /etc/hosts
    regexp: '^10\.0\.0\.1'
    state: absent

- name: insert after
  lineinfile:
    path: /etc/ssh/sshd_config
    insertafter: '^#?PermitRootLogin'
    line: 'AllowUsers deploy admin'
    validate: 'sshd -t -f %s'

yaml

- name: block config
  blockinfile:
    path: /etc/ssh/sshd_config
    marker: "# {mark} ANSIBLE MANAGED - SECURITY"
    block: |
      PermitRootLogin no
      PasswordAuthentication no
      PubkeyAuthentication yes
      X11Forwarding no
    validate: 'sshd -t -f %s'
    backup: yes

yaml

- name: replace pattern
  replace:
    path: /etc/selinux/config
    regexp: '^SELINUX=.*'
    replace: 'SELINUX=enforcing'

نکات:

    regexp با ^ و $ برای دقت

    validate در فایل‌های سرویس اجباری

    هرگز lineinfile بدون regexp → append می‌کند

    blockinfile marker برای idempotency ({mark} حذف/اضافه)

    برای تغییرات پیچیده: template به‌جای lineinfile

۳.۵ ansible.posix.synchronize (rsync)

کاربرد production: انتقال سریع فایل‌های بزرگ، dir sync با exclude.
yaml

synchronize:
  src:
  dest:
  mode:                    # push (default) | pull
  delete:                  # yes → حذف فایل‌های حذف‌شده روی مقصد
  recursive:               # yes
  rsync_opts:              # ["--exclude=.git", "--chmod=D755,F644"]
  rsync_path:              # "sudo rsync" اگر become لازم
  compress:                # yes
  checksum:                # yes → idempotency دقیق
  delay_updates:           # yes → برای live dir
  archive:                 # yes (پیش‌فرض)
  exclude:
  include:

مثال production:
yaml

- name: deploy static assets
  synchronize:
    src: ./dist/
    dest: /var/www/html/
    delete: yes
    rsync_opts:
      - "--exclude=*.map"
      - "--chmod=D755,F644"
    checksum: yes
  delegate_to: "{{ inventory_hostname }}"

نکات:

    synchronize روی control node اجرا می‌شود (نه remote) → با delegate_to: {{ inventory_hostname }} به remote منتقل شود

    delete: yes خطرناک است → فقط با checksum و تست

    برای فایل بزرگ: سریع‌تر از copy

۵.۳ community.crypto.x509_certificate / openssl_privatekey / openssl_csr

کاربرد production: مدیریت SSL/TLS certificate (Let's Encrypt، internal CA، self-signed).
yaml

- name: generate private key
  openssl_privatekey:
    path: /etc/ssl/private/app.key
    size: 4096
    type: RSA
    mode: '0600'
    owner: root
  no_log: true

- name: generate CSR
  openssl_csr:
    path: /etc/ssl/certs/app.csr
    privatekey_path: /etc/ssl/private/app.key
    common_name: app.example.com
    subject_alt_name:
      - DNS:app.example.com
      - DNS:www.app.example.com
      - IP:10.0.0.1
    country_name: IR
    organization_name: Example

- name: sign with internal CA
  x509_certificate:
    path: /etc/ssl/certs/app.crt
    csr_path: /etc/ssl/certs/app.csr
    provider: ownca
    ownca_path: /etc/ssl/certs/ca.crt
    ownca_privatekey_path: /etc/ssl/private/ca.key
    ownca_not_after: +365d

- name: deploy to nginx
  copy:
    src: /etc/ssl/certs/app.crt
    dest: /etc/nginx/ssl/app.crt

نکات:

    no_log: true روی private key

    mode: '0600' اجباری

    subject_alt_name مدرن (نه subject.subjectAltName)

    برای Let's Encrypt: acme_certificate یا certbot از طریق command

        sysctl_file: /etc/sysctl.d/99-hardening.conf
        reload: yes
      loop:
        - net.ipv4.tcp_syncookies
        - net.ipv4.conf.all.rp_filter
        - net.ipv4.conf.all.accept_redirects
        - net.ipv4.ip_forward

    - name: firewall
      ansible.posix.firewalld:
        service: "{{ item }}"
        permanent: yes
        state: enabled
        immediate: yes
      loop: [ssh, https]

    - name: auditd
      service:
        name: auditd
        state: started
        enabled: yes

    - name: disable unused services
      systemd:
        name: "{{ item }}"
        state: stopped
        enabled: no
      loop: [telnet.socket, rsh.socket]
      ignore_errors: yes

۱۹.۳ Rolling cluster upgrade (Kubernetes)
yaml

- hosts: k8s-worker
  serial: 1
  any_errors_fatal: true

  tasks:
    - name: drain
      kubernetes.core.k8s_drain:
        node: "{{ inventory_hostname }}"
        state: drain
        ignore_daemonsets: yes
        delete_emptydir_data: yes
      delegate_to: "{{ groups['k8s-master'][0] }}"

    - name: upgrade packages
      dnf: { name: "kubeadm-1.29.0-*", state: present, allow_downgrade: no }

    - name: upgrade node
      command: kubeadm upgrade node
      args: { creates: /var/lib/kubelet/.upgraded-1.29.0 }

    - name: restart kubelet
      systemd: { name: kubelet, state: restarted }

    - name: uncordon
      kubernetes.core.k8s_drain:
        node: "{{ inventory_hostname }}"
        state: uncordon
      delegate_to: "{{ groups['k8s-master'][0] }}"

    - name: wait ready
      kubernetes.core.k8s_info:
        kind: Node
        name: "{{ inventory_hostname }}"
      register: node
      until: node.resources[0].status.conditions | selectattr('type','equalto','Ready') | map(attribute='status') | first == "True"
      retries: 30
      delay: 10
      delegate_to: "{{ groups['k8s-master'][0] }}"
